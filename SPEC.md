# Document the Embeddings extension in the docs

## Problem
Building the docs with `uv run make -C docs html SPHINXOPTS="-W --keep-going -n"` fails: it
emits four `WARNING: py:class reference target not found:
pystac.extensions.embeddings.EmbeddingsExtension` warnings, which are treated as errors by `-W`,
so the build exits non-zero. The warnings come from the autogenerated docstrings of the `emb`
accessors in `pystac/extensions/ext.py`. The cause is that the embeddings extension is a real,
importable workspace package but is not documented in the Sphinx API reference, so its
`EmbeddingsExtension` class is never registered as a valid cross-reference target. Every other
extension resolves because it is documented.

## Solution
Document the embeddings extension in the Sphinx API reference, consistent with all the other
extensions, so the `EmbeddingsExtension` cross-reference resolves and the build passes with no
warnings. No runtime code is changed.

## User stories
1. As a PySTAC developer, I want the docs to build cleanly with `-W --keep-going -n`, so that the
   docs job passes.
2. As a PySTAC user, I want the embeddings extension to appear in the API reference alongside the
   other extensions, so that I can find and read its documentation.

## Decisions
- Fix the warnings by documenting the embeddings extension rather than suppressing them.
- Create an API reference page for the embeddings extension module, following the same style as the
  other extension pages (`automodule` with `:members:` and `:undoc-members:`).
- Register the embeddings extension class in the extensions autosummary.
- Add the embeddings extension to the Extensions list in the API reference index.
- Leave `pystac/extensions/ext.py` unchanged; its `emb` accessor type annotations and imports stay
  as they are.

## Checks
- Run `uv run make -C docs html SPHINXOPTS="-W --keep-going -n"`: the build must exit 0 with no
  warnings.
- The four warnings for `pystac.extensions.embeddings.EmbeddingsExtension` must no longer appear.
- The new embeddings API reference page is picked up by the `:glob:` in the extensions index and
  appears in the generated docs.

## Must keep working
- All other extension API pages continue to build without warnings.
- The runtime behavior and public API of `pystac/extensions/ext.py` are unchanged.
- The embeddings extension remains importable as `pystac.extensions.embeddings`.

## Out of scope
- Changing the runtime `emb` accessor API or its type annotations.
- Editing docstrings in `pystac/extensions/ext.py`.
- Updating the narrative extension list in the concepts guide.
- Adding the embeddings extension to package or release configuration.
